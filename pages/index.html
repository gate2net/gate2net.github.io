How it works

One SSH command. A public URL.

Your service stays on your machine. Visitors reach it through the gate, every byte encrypted on the way.

requestsresponsesSSH encryption end to end
From your terminal

Dial the gate.

The subdomain goes in front of the port. Every request is logged as it passes.

ssh offers the keys in ~/.ssh (id_ed25519, id_ecdsa, id_rsa…) and those in your agent: nothing to add when one of them is on the subdomain.

For a key kept elsewhere, such as one made just for intergate with ssh-keygen -t ed25519 -f ~/.ssh/intergate. With many keys in your agent, add -o IdentitiesOnly=yes.

What you get

Your gate, your rules.

Keys per subdomain

Only the SSH keys you add to a subdomain can open it.

Passkeys & email codes

No passwords. A code by email, then your fingerprint.

Public, team or private

Choose who can open each subdomain. Your app never sees the login.

Live dashboard

Who is connected, from where, requests and traffic. One click to cut it.

HTTPS by itself

Let's Encrypt certificates for each subdomain as it is registered, or one wildcard certificate through Cloudflare, Google Cloud DNS, Route 53 or DigitalOcean, set up from the dashboard.

A wizard in the terminal

intergate config: set up, add keys and users without the browser.

TCP ports

Databases, SSH, game servers on a port of their own, tcp://gate.example.com:30042, with the same ssh -R.

UDP too

Minecraft Bedrock, WireGuard, DNS… through the intergate client, run with one curl line.

Allow lists

Each port only lets in the addresses you choose: yours, by default.

Install

Pick your launchpad.

Point gate.example.com and *.gate.example.com at the server, then:

$ curl -fsSL https://jgermade.github.io/intergate/setup.sh | sh
$ wget -qO- https://jgermade.github.io/intergate/setup.sh | sh

Linux and macOS. It installs the binary, opens the setup wizard and, with systemd, runs intergate as a service, then gives you a one-time link to the dashboard’s setup: email delivery and your account. Run it again to update, reconfigure or uninstall.

The same, for machines without curl, such as a minimal Debian: the installer then downloads with wget too.

# configuration and state live in the volume
$ docker volume create intergate
$ docker run -it --rm -v intergate:/data ghcr.io/jgermade/intergate config
$ docker run -d --name intergate --restart unless-stopped -v intergate:/data \
    -p 80:80 -p 443:443 -p 2222:2222 ghcr.io/jgermade/intergate

Choose Let's Encrypt in the wizard: intergate gets a certificate for each subdomain on its own. Then docker exec intergate intergate setup-url gives the link to the dashboard’s setup, and docker exec -it intergate intergate config manages it from the terminal.

$ helm install intergate oci://ghcr.io/jgermade/charts/intergate \
    --set domain=gate.example.com \
    --set traefik.tls.certResolver=letsencrypt-dns
# values.yaml of Traefik’s own chart
ports:
  ssh:
    port: 2222
    expose: {default: true}
    exposedPort: 2222
    protocol: TCP

An IngressRoute for the dashboard and every subdomain, and SSH over a Traefik TCP entry point with the PROXY protocol. Then kubectl exec deploy/intergate -- intergate setup-url gives the link to the dashboard’s setup. See the chart, also in a classic repository: helm repo add intergate https://jgermade.github.io/intergate/charts.

Traefik opens the SSH port once its chart declares the entry point. Keep exposedPort and intergate’s ssh.publicPort the same; port 22 only works on an address no other sshd uses.
