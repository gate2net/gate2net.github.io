# Wildcard certificate through DNS providers

Status: completed on branch `claude/blissful-gates-fpscb0` (no PR yet).

## The ask

intergate serves `*.gate.example.com`, so plugins for the DNS providers of
that wildcard domain (Google Cloud, Cloudflare…). Then, refined: a fresh
install should just work on `gate.example.com`, and the DNS provider for a
wildcard certificate is set up from the dashboard, in an Admin tab next to
the SMTP relay.

## What was built

- `internal/dns`: providers as plugins. `Provider` replaces or deletes the
  record set of a name and type (`Set`, `Delete`); each provider registers
  a `Spec` (name, title, help, fields with `Required`, `Secret`, `Upload`,
  `ConfigOnly`, `Path`) from its own file. Built in, on `net/http` without
  SDKs:
  - `cloudflare`: API token, optional `zone_id`; TXT content quoted, A/AAAA/
    CNAME never proxied; results filtered by name client-side as well.
  - `gcp`: Cloud DNS v1 rrsets (GET, POST, PATCH, DELETE), public zones
    only; credentials from `credentials_json` (dashboard: the key file's
    content), `credentials_file` (configuration only) or Application Default
    Credentials (`golang.org/x/oauth2/google`, adding the small
    `cloud.google.com/go/compute/metadata` module).
  - `route53`: Signature Version 4 by hand (checked against AWS's
    get-vanilla test vectors), UPSERT/exact DELETE, `\052` names; keys from
    the settings, `AWS_*`, or the EC2 instance role (IMDSv2).
  - `digitalocean`: token, optional `domain`.
  - `exec` (configuration only): `PROGRAM set NAME TYPE TTL VALUE...` and
    `PROGRAM delete NAME TYPE`.
  - Zones found from the most specific candidate up (`_` labels skipped),
    cached per name. `Propagation` finds the zone's authoritative
    nameservers (NS walk) and polls TXT on each (`net.Resolver` dialing that
    server); unreachable ones are left out. `PropagationAt` for
    `dns.nameservers`.
- `internal/wildcard`: the certificate for `domain` and `*.domain` with
  `x/crypto/acme` (DNS-01): account key and certificate in
  `<data_dir>/wildcard/`; renewal at a third of the life left; backoff 5, 10,
  20, 40 min then hourly; `Configure(nil)` stops renewals and the cert is
  served until it expires; optional wildcard record (`*.domain CNAME
  domain`, deleting A/AAAA first); `Status` with the current step for the
  dashboard. `CreateCertFromOrder` (not `CreateOrderCert`): Pebble answers
  the finalization with `processing` and no `Location`.
- `internal/acmetest`: a fake ACME CA (enough of RFC 8555 for `x/crypto/acme`
  and autocert) with an in-memory zone that DNS-01 is checked against;
  finalization answers like Pebble's.
- Config `dns:` (`provider`, a block per provider's settings inline,
  `wildcard_record`, `propagation_timeout` 2m, `nameservers`); needs
  `http.tls.acme`; relative `Path` settings resolve against the file. The
  file wins over the dashboard.
- `internal/settings/dns.go`: the dashboard's provider in the `settings`
  table (`dns` key), secrets sealed with AES-256-GCM under a key derived for
  "dns credentials" (AD per provider and field); an empty secret keeps the
  stored one for the same provider; `ConfigOnly` providers and fields are
  refused.
- Server: the manager exists when `http.tls.acme` is on; TLS asks it first
  and falls back to autocert (and always for `acme-tls/1` hellos). A
  configuration file's broken provider stops startup; a dashboard's shows
  its error in the tab.
- Dashboard: Admin → **DNS** (`boot.wildcard`), `GET/PUT/DELETE
  /api/admin/dns`, `POST /api/admin/dns/retry`. Owners save after a check
  (TXT `_intergate-check.<domain>` added and removed); admins read. The tab
  shows the certificate (facts), the step while issuing (polls every 2 s),
  the error with "Try again now", the wildcard record, and whether
  `*.domain` resolves already (a random name looked up, cached a minute) to
  default the switch. GCP's key is a file input. "SMTP relay" is "SMTP" on
  phones so the four tabs fit.
- `intergate status` prints a `tls:` line; the wizard's next steps point to
  Admin → DNS. README section, example config, landing line.
- Tests: providers against fakes of their APIs with one conformance run
  each; propagation against `dnsmessage` nameservers; the manager against
  `acmetest` (issue, reload, renew, stop, failures); settings sealing; e2e
  `TestWildcardCertificateFromTheDashboard` runs the whole server over TLS
  and checks the certificate served per SNI before and after.

## Verified by hand

- Pebble v2.10.1 + `pebble-challtestsrv`, the real binary with the `exec`
  provider calling challtestsrv's API and `nameservers: [127.0.0.1:8053]`:
  wildcard issued, served for `gate.test` and `myapp.gate.test`, the
  per-host path (no provider) still issued through autocert.
- The DNS tab in Chromium (Playwright): empty, form (Cloudflare, GCP),
  refused credentials, phone width, and an issued certificate.

## Not done / not verified

- No real Cloudflare, Google Cloud, Route 53 or DigitalOcean account was
  used: only fakes of their APIs, written from their documentation.
- Route 53 credentials from IRSA/web identity or ECS/EKS Pod Identity are
  not supported (static keys, `AWS_*`, EC2 instance role only).
- `_acme-challenge` CNAME delegation (acme-dns style) is not followed.
- The wizard does not ask for a provider: the dashboard (or the file) does.
