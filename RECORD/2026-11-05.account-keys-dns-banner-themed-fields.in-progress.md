# Account SSH keys, DNS banner, themed select and file picker

Status: in progress on branch `claude/blissful-gates-fpscb0`, restarted
from `main` after #24 (v0.0.25) was merged. Committed before the session's
quota ran out: the Go side is tested, the dashboard side was **not looked
at in a browser yet**.

## The ask

After installing with `traefik.tls.passthrough`:

1. On the first visit, a banner between the header and the page saying
   that without the DNS set up, subdomains won't work.
2. The DNS form looked generic (native select and file input): use the
   site's styles.
3. `/account` in tabs: account details, SSH keys, passkeys.
4. SSH keys of the user, added once, then to one or several subdomains
   with a select using `<selectedcontent>`.

## What was built

- **Banner** (`app.html`, `.banner` in `app.css`): owners only, while
  intergate gets certificates from Let's Encrypt and there is no DNS
  provider nor a wildcard certificate in use; "Not now" hides it in that
  browser (localStorage, wrapped in try/catch). Boot `wildcard` is now an
  object `{provider, ready, resolves}` (`resolves`: whether `*.<domain>`
  resolves, looked up for owners only, cached a minute). Two texts, both
  true: *.domain does not resolve → "Subdomains won't work yet" (warn);
  it resolves → each subdomain gets its own certificate as it is
  registered, set up DNS for one for all (info). The user asked for "won't
  work" always; with per-host certificates at registration they do work,
  so it only says so when `*.domain` does not resolve. Links to
  `/admin?tab=dns`; the Admin page opens that tab from `?tab=` and the
  banner follows a save or removal (`followDNS`).
- **Theme components** `select.html` (customizable select:
  `appearance: base-select`, `<button><selectedcontent>`, options with an
  icon from `icons.js`, a label and a hint; native fallback shows
  "label · hint") and `file-picker.html` (a field with a themed button and
  the file's name; `pick` brings `{name, text}`). Both in the demo
  (`demo.html` sections, `GROUPS`, `usage.js` `TITLES`/`USAGE`).
- They replace every native select: the DNS provider (items with each
  provider's new `Spec.Summary`), the GCP key file (FilePicker), the SMTP
  relay's encryption (the port follows it when it is one of the defaults),
  and the TCP port presets.
- **Account keys**: migration 5, table `user_keys` (unique per user and
  fingerprint) and `ssh_keys.user_key_id` (`ON DELETE CASCADE`). Store:
  `AddUserKey`, `UserKeys`, `UserKey`, `RenameUserKey` (renames the
  copies), `DeleteUserKey` (returns where it was), `AttachUserKey`,
  `UserKeyAttachments`; `Key.UserKeyID`. `GrantsForKey` skips keys of a
  disabled account, on anyone's subdomain. Manage (`userkeys.go`):
  `AddUserKeys` (50 per account, `KeysPerAccount`), `RenameUserKey`,
  `RemoveUserKey` (closes the tunnels and ports it opened everywhere),
  `AttachUserKey` (own keys only, subdomain key limit);
  `SetUserDisabled`/`DeleteUser` also close tunnels opened with the user's
  keys on others' subdomains. API: `GET/POST /api/account/keys`,
  `PATCH/DELETE /api/account/keys/{id}` (DELETE answers `removed_from`),
  `GET /api/account` adds `keys` and `keys_limit`, `POST
  /api/subdomains/{name}/keys` takes `account_key`, `POST /api/subdomains`
  takes `account_keys`, and `key_list` items say `from_account`.
- **Dashboard**: `/account` has tabs Account / SSH keys / Passkeys
  (`?tab=keys|passkeys`; Sign out moved under the profile). The SSH keys
  tab lists keys with the subdomains they are on, adds in a dialog,
  renames in place, and asks before removing, naming the subdomains that
  lose it. `keys-form.html` takes `:account`; for a subdomain it offers
  the account's keys it does not have yet in a `Select` ("From your
  account", then "or paste one"). The register form has "SSH key from your
  account" (None by default, or the only key). The subdomain's keys table
  marks "account key".
- Tests: `TestUserKeys` (store: conflicts, attach, rename, disabled
  owner, delete everywhere, account deletion), `TestAccountKeys` (e2e:
  add, register with it, attach, refuse twice and another account's key,
  open a tunnel, rename, remove → tunnel closed, key gone, SSH refused),
  the boot's `wildcard` in `TestWildcardCertificateFromTheDashboard`.
  `go test -race ./...` passes.
