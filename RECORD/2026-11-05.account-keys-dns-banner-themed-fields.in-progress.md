# Account SSH keys, DNS banner, themed select and file picker

Status: in progress on branch `claude/blissful-gates-fpscb0`, restarted
from `main` after #24 (v0.0.25) was merged. The Go side is tested; the
dashboard was checked in a browser in a second session (below). Native
select fallback (a browser without `appearance: base-select`) not seen.

## The ask

After installing with `traefik.tls.passthrough`:

1. On the first visit, a banner between the header and the page saying
   that without the DNS set up, subdomains won't work.
2. The DNS form looked generic (native select and file input): use the
   site's styles.
3. `/account` in tabs: account details, SSH keys, passkeys.
4. SSH keys of the user, added once, then to one or several subdomains
   with a select using `<selectedcontent>`.

## What was built

- **Banner** (`app.html`, `.banner` in `app.css`): owners only, while
  intergate gets certificates from Let's Encrypt and there is no DNS
  provider nor a wildcard certificate in use; "Not now" hides it in that
  browser (localStorage, wrapped in try/catch). Boot `wildcard` is now an
  object `{provider, ready, resolves}` (`resolves`: whether `*.<domain>`
  resolves, looked up for owners only, cached a minute). Two texts, both
  true: *.domain does not resolve → "Subdomains won't work yet" (warn);
  it resolves → each subdomain gets its own certificate as it is
  registered, set up DNS for one for all (info). The user asked for "won't
  work" always; with per-host certificates at registration they do work,
  so it only says so when `*.domain` does not resolve. Links to
  `/admin?tab=dns`; the Admin page opens that tab from `?tab=` and the
  banner follows a save or removal (`followDNS`).
- **Theme components** `select.html` (customizable select:
  `appearance: base-select`, `<button><selectedcontent>`, options with an
  icon from `icons.js`, a label and a hint; native fallback shows
  "label · hint") and `file-picker.html` (a field with a themed button and
  the file's name; `pick` brings `{name, text}`). Both in the demo
  (`demo.html` sections, `GROUPS`, `usage.js` `TITLES`/`USAGE`).
- They replace every native select: the DNS provider (items with each
  provider's new `Spec.Summary`), the GCP key file (FilePicker), the SMTP
  relay's encryption (the port follows it when it is one of the defaults),
  and the TCP port presets.
- **Account keys**: migration 5, table `user_keys` (unique per user and
  fingerprint) and `ssh_keys.user_key_id` (`ON DELETE CASCADE`). Store:
  `AddUserKey`, `UserKeys`, `UserKey`, `RenameUserKey` (renames the
  copies), `DeleteUserKey` (returns where it was), `AttachUserKey`,
  `UserKeyAttachments`; `Key.UserKeyID`. `GrantsForKey` skips keys of a
  disabled account, on anyone's subdomain. Manage (`userkeys.go`):
  `AddUserKeys` (50 per account, `KeysPerAccount`), `RenameUserKey`,
  `RemoveUserKey` (closes the tunnels and ports it opened everywhere),
  `AttachUserKey` (own keys only, subdomain key limit);
  `SetUserDisabled`/`DeleteUser` also close tunnels opened with the user's
  keys on others' subdomains. API: `GET/POST /api/account/keys`,
  `PATCH/DELETE /api/account/keys/{id}` (DELETE answers `removed_from`),
  `GET /api/account` adds `keys` and `keys_limit`, `POST
  /api/subdomains/{name}/keys` takes `account_key`, `POST /api/subdomains`
  takes `account_keys`, and `key_list` items say `from_account`.
- **Dashboard**: `/account` has tabs Account / SSH keys / Passkeys
  (`?tab=keys|passkeys`; Sign out moved under the profile). The SSH keys
  tab lists keys with the subdomains they are on, adds in a dialog,
  renames in place, and asks before removing, naming the subdomains that
  lose it. `keys-form.html` takes `:account`; for a subdomain it offers
  the account's keys it does not have yet in a `Select` ("From your
  account", then "or paste one"). The register form has "SSH key from your
  account" (None by default, or the only key). The subdomain's keys table
  marks "account key".
- Tests: `TestUserKeys` (store: conflicts, attach, rename, disabled
  owner, delete everywhere, account deletion), `TestAccountKeys` (e2e:
  add, register with it, attach, refuse twice and another account's key,
  open a tunnel, rename, remove → tunnel closed, key gone, SSH refused),
  the boot's `wildcard` in `TestWildcardCertificateFromTheDashboard`.
  `go test -race ./...` passes.

## Verified in a browser (second session)

Pebble (`ghcr.io/letsencrypt/pebble`, `PEBBLE_VA_ALWAYS_VALID=1`) and the
image from the Dockerfile on a Docker network, `directory_url` pointed at
Pebble and `SSL_CERT_FILE` at its minica root; Chromium through Playwright
with `--host-resolver-rules` for `gate.test`, signed in with the code from
`log_only`. Go is not installed on that Mac: tests ran in `golang:1.26`.

Found and fixed:

- **The whole app failed to render**: `app.html`'s `$:` statement ran over
  two lines, and jq79 takes a `$:` statement as one line ("Unexpected token
  '}'"). Now on one line.
- **`Select` fell back to the native look in Chromium**: jq79 scopes
  `<style scoped>` through the CSSOM, and Chromium writes
  `::picker(select)` back as `::picker`, which drops both rules that use it
  (and with them `appearance: base-select`). They moved to a plain `<style>`
  in `select.html` (`select.select…`). No other theme component loses rules
  that way (checked each by scoping its CSS as jq79 does).
- The open list was white with white text on the dark tone (the demo): its
  options are now `data-tone="light"` with their own `color`, and it blurs
  what is behind (`--ig-blur`), as the other HUD materials.
- "From your account": the Select took the row and pushed "Add the key" out
  (`.form-row > box > *` is `flex: 1 0 auto`; the override was on the box,
  which is `display: contents`). Now on the box's child.
- The banner touched the bar on desktop (`.wrap`'s padding in the 640px
  query won over `.banner`'s): a margin now.
- On a phone the account's keys table wrapped the fingerprint over six
  lines: its column is hidden there and a short one goes under the type.
- The setup's SMTP encryption was still a native `select.field`: now the
  `Select` (same items as Admin → SMTP relay; the port follows it as
  there), and `select.field` is gone from `app.css`. Not seen in a browser
  (the test server's email was `log_only`, so there was no setup).

Seen working: the banner (warn text, link to Admin → DNS, "Not now" kept
after a reload), account tabs, keys added inline then in the dialog,
registering with an account key, attaching another from a subdomain's
dialog ("account key" mark), rename in place (copies renamed), the remove
dialog naming the subdomains and the key gone from them after, Admin → DNS
(provider Select open, GCP with the FilePicker and a file chosen), the TCP
port presets, the theme demo's two sections, phone width (390px). The
dashboard has one colour scheme (no `prefers-color-scheme`), so "light and
dark" means the two tones, both seen. `go vet` and `go test -race ./...`
pass. README: account keys, the banner, revocation, the theme's list.

## Account keys in `intergate config`

- Admin socket: `GET/POST /v1/users/{id}/keys`, `DELETE
  /v1/users/{id}/keys/{key}` (answers `removed_from`); `POST
  /v1/subdomains/{name}/keys` takes `account_key` (a key of the
  subdomain's owner), `POST /v1/subdomains` takes `account_keys` (of the
  owner's). `api.AccountKey`/`NewAccountKeys` are shared with the
  dashboard.
- Wizard: Users → a user is now a menu: its account's keys and the
  subdomains each is on, add keys, remove one (says which subdomains lost
  it), Disable/Enable (with the confirmation as before). A subdomain
  offers "Add a key from <owner>'s account" when the owner has keys it does
  not; registering asks for one of the owner's keys when there are any
  (the only one by default, as the dashboard). Its keys list marks
  "(account key)".
- `TestWizardAccountKeys` (add to the account, to a subdomain, register
  another with it, remove it from both); `TestWizardManagesRunningServer`
  picks Disable from the user's menu now.
- The banner also shows on Admin → DNS: wanted, until a provider is set.
